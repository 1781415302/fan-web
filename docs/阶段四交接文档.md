### 3.2 视频文件服务

#### 3.2.1 路径解析：`services/scanner.go` 新增方法

在 `ScannerService` 上新增一个**公开**方法 `ResolveFilePath`，复用已有的 `resolveDirectory` 逻辑：

```
func (s *ScannerService) ResolveFilePath(dirPath, fileName string) (string, error)
```

**逻辑**：
1. 调用 `s.resolveDirectory(dirPath)` 获取已解析的目录绝对路径
2. 校验 `fileName`：不允许包含 `/`、`\`、`..`、null 字节
3. `filepath.Join(dir, fileName)` 拼接完整路径
4. `filepath.EvalSymlinks` 解析符号链接
5. `filepath.Rel(dir, resolved)` 确认结果仍在目录内
6. 返回解析后的绝对路径

#### 3.2.2 视频流接口：`handlers/episode.go`

新建 `EpisodeHandler` 结构体，依赖 `*services.AuthService`（解析 token）和 `*services.ScannerService`（解析路径）：

```
type EpisodeHandler struct {
    auth    *services.AuthService
    scanner *services.ScannerService
}
```

**接口**：`GET /api/episodes/:id/stream?token=xxx`

**为什么用 query 参数传 token**：浏览器 `<video>` 标签发起的请求不会携带 `Authorization` 头，所以不能复用 `JWTAuth` 中间件。通过 query 参数传递 token 是视频流场景的标准做法。

**处理流程**：
1. 从 `c.Query("token")` 获取 token，为空则从 `Authorization` 头获取（兼容）
2. 调用 `authService.ParseToken(token)` 解析，失败返回 `CodeUnauthenticated`
3. 从 URL 参数获取 `episode_id`，`strconv.ParseInt` 解析
4. `database.GetEpisodeByID(id)` 获取 episode 记录（需在 `database/anime.go` 新增此函数）
5. `database.GetAnimeByID(episode.AnimeID)` 获取 anime 记录
6. `scanner.ResolveFilePath(anime.FilePath, episode.FilePath)` 解析完整文件路径
7. `c.File(fullPath)` 或 `http.ServeFile(c.Writer, c.Request, fullPath)` 提供文件

**`http.ServeFile` 自动支持**：
- HTTP Range 请求（206 Partial Content）→ 进度条拖拽
- Content-Type 检测
- Last-Modified / If-Modified-Since 缓存

**安全**：路径经过 `ValidateRelativeVideoPath` + `ResolveFilePath` 双重校验，防止路径遍历。

**`database/anime.go` 需新增**：
```
func GetEpisodeByID(id int64) (*models.Episode, error)
```
用 `episodeSelect + " WHERE id = ?"` 查询，复用 `scanEpisode`。

### 3.3 播放进度数据层 `database/progress.go`

#### 3.3.1 函数签名

```
func GetProgress(userID, episodeID int64) (*models.WatchProgress, error)
func UpsertProgress(userID, episodeID int64, position int, watched bool) error
func ListProgressByAnime(userID, animeID int64) ([]models.WatchProgress, error)
func CountWatchedByAnime(userID, animeID int64) (int, error)
```

#### 3.3.2 实现要点

**`GetProgress`**：
- SQL: `SELECT id, user_id, episode_id, position, watched, updated_at FROM watch_progress WHERE user_id = ? AND episode_id = ?`
- 用 `scanProgress` 辅助函数扫描（需新建，仿照 `scanUser` 模式）
- `watched` 字段是 INTEGER 0/1，需转为 bool
- 如果 `sql.ErrNoRows`，返回 `&WatchProgress{Position: 0, Watched: false}` 而非错误（无记录等于未观看）

**`UpsertProgress`**：
- 使用 SQLite UPSERT 语法（依赖 `(user_id, episode_id)` 唯一索引）：
  ```sql
  INSERT INTO watch_progress (user_id, episode_id, position, watched, updated_at)
  VALUES (?, ?, ?, ?, CURRENT_TIMESTAMP)
  ON CONFLICT(user_id, episode_id) DO UPDATE SET
      position = excluded.position,
      watched = excluded.watched,
      updated_at = excluded.updated_at
  ```
- `watched` 参数：bool 转 int（`0` 或 `1`）

**`ListProgressByAnime`**：
- JOIN episodes 表：
  ```sql
  SELECT wp.id, wp.user_id, wp.episode_id, wp.position, wp.watched, wp.updated_at
  FROM watch_progress wp
  JOIN episodes e ON wp.episode_id = e.id
  WHERE wp.user_id = ? AND e.anime_id = ?
  ORDER BY e.ep_number ASC
  ```

**`CountWatchedByAnime`**：
- SQL: `SELECT COUNT(*) FROM watch_progress wp JOIN episodes e ON wp.episode_id = e.id WHERE wp.user_id = ? AND e.anime_id = ? AND wp.watched = 1`
- 用于番剧列表页显示进度

#### 3.3.3 scan 辅助函数

```
func scanProgress(row scanner) (*models.WatchProgress, error)
```
扫描字段顺序：`id, user_id, episode_id, position, watched, updated_at`。`watched` 用 `int` 接收再转 `bool`（仿照 `scanUser` 中 `is_admin` 的处理方式）。

### 3.4 播放进度接口 `handlers/episode.go`

#### 3.4.1 接口清单

| 方法 | 路径 | 鉴权方式 | 说明 |
|------|------|---------|------|
| GET | `/api/episodes/:id/stream` | query param token | 视频流（Range 支持） |
| GET | `/api/progress/:episode_id` | JWT header | 获取某集播放进度 |
| POST | `/api/progress/:episode_id` | JWT header | 上报播放进度 |
| GET | `/api/progress/anime/:anime_id` | JWT header | 获取某番剧所有集进度 |

#### 3.4.2 获取进度 `GET /api/progress/:episode_id`

- 从 `middleware.CurrentUserID(c)` 获取 userID
- 解析 `:episode_id`
- 调用 `database.GetProgress(userID, episodeID)`
- 返回：`{ "position": 120, "watched": false, "updated_at": "..." }`

#### 3.4.3 上报进度 `POST /api/progress/:episode_id`

**请求体**：
```json
{
  "position": 120,
  "watched": false
}
```

- `position`：int，当前播放位置（秒），必填，≥ 0
- `watched`：bool，是否已看完，可选，默认 false

**处理流程**：
1. 解析 `:episode_id` 和请求体
2. 校验 `position >= 0`
3. 从 `middleware.CurrentUserID(c)` 获取 userID
4. 调用 `database.UpsertProgress(userID, episodeID, position, watched)`
5. 返回 `null`

**watched 判定逻辑说明**：由前端计算。前端从播放器获取视频总时长 `duration`，当 `position / duration >= 0.9` 时，POST 请求中 `watched` 设为 `true`。后端不做计算，只存储。

#### 3.4.4 获取番剧进度 `GET /api/progress/anime/:anime_id`

- 从 `middleware.CurrentUserID(c)` 获取 userID
- 调用 `database.ListProgressByAnime(userID, animeID)`
- 返回数组：`[{ "episode_id": 1, "position": 120, "watched": true, "updated_at": "..." }, ...]`

### 3.6 路由注册 `main.go` 修改

新增初始化：
- 创建 `EpisodeHandler`，注入 `authService` 和 `scannerService`

新增路由（注册在 `protected` 组下，即需要 JWT 认证）：
```
protected.GET("/episodes/:id/stream", episodeHandler.Stream)     // 注意：此路由的 token 从 query param 读取
protected.GET("/progress/:episode_id", episodeHandler.GetProgress)
protected.POST("/progress/:episode_id", episodeHandler.ReportProgress)
protected.GET("/progress/anime/:anime_id", episodeHandler.AnimeProgress)
```

> **注意**：`/api/episodes/:id/stream` 虽然在 `protected` 组下注册（会经过 `JWTAuth` 中间件），但 `JWTAuth` 只检查 `Authorization` 头。视频流请求携带的是 `?token=xxx`，所以 `JWTAuth` 会返回 401。
>
> **解决方案**：将 `/api/episodes/:id/stream` 注册在**公开路由区**（不在 `protected` 下），由 handler 内部自行验证 query param 中的 token。其余 3 个进度路由正常放在 `protected` 下。

最终路由注册：
```go
// 公开区（episodeHandler 内部验证 token）
api.GET("/episodes/:id/stream", episodeHandler.Stream)

// 认证区
protected.GET("/progress/:episode_id", episodeHandler.GetProgress)
protected.POST("/progress/:episode_id", episodeHandler.ReportProgress)
protected.GET("/progress/anime/:anime_id", episodeHandler.AnimeProgress)
```

#### 4.6.2 组件结构

```
<script setup lang="ts">
// 依赖：vue (ref, computed, onMounted, onBeforeUnmount, watch)
//       vue-router (useRoute, useRouter)
//       artplayer (默认导入)
//       api/anime (getAnime, listEpisodes)
//       api/progress (getProgress, reportProgress)
//       api/episode (getStreamUrl)
//       types/anime (Anime, Episode)
//       types/progress (EpisodeProgress)

// 路由参数
const route = useRoute()
const animeId = computed(() => Number(route.params.id))
const epId = computed(() => Number(route.params.epId))

// 数据
const anime = ref<Anime | null>(null)
const episodes = ref<Episode[]>([])
const progress = ref<EpisodeProgress>({ position: 0, watched: false, updated_at: '' })
const loading = ref(true)
const error = ref('')

// ArtPlayer 实例
let art: Artplayer | null = null
let lastReportTime = 0  // 上次上报时间戳

// 当前集数在列表中的索引
const currentIdx = computed(() => episodes.value.findIndex(e => e.id === epId.value))
const prevEpisode = computed(() => currentIdx.value > 0 ? episodes.value[currentIdx.value - 1] : null)
const nextEpisode = computed(() => currentIdx.value < episodes.value.length - 1 ? episodes.value[currentIdx.value + 1] : null)
```

#### 4.6.3 生命周期流程

**`onMounted` / `watch(epId)`**：
1. 设置 `loading = true`
2. 并发请求：`getAnime(animeId)` + `listEpisodes(animeId)` + `getProgress(epId)`
3. 存储数据到 ref
4. 调用 `initPlayer()` 初始化播放器
5. 设置 `loading = false`

**`initPlayer()`**：
1. 获取视频 URL：`getStreamUrl(epId.value)`
2. 创建 ArtPlayer 实例：
   ```
   new Artplayer({
     container: '.player-container',  // 模板中的 div ref
     url: videoUrl,
     autoplay: false,
     playbackRate: true,             // 显示倍速菜单
     playbackRates: [0.5, 1, 1.25, 1.5, 2],
     fullscreen: true,
     fullscreenWeb: true,            // 移动端网页全屏
     setting: true,
     pip: true,                      // 画中画
   })
   ```
3. 注册事件：
   - `art.on('ready', ...)` — 播放器就绪，如果 `progress.position > 10`，执行 `art.currentTime = progress.position`
   - `art.on('video:timeupdate', ...)` — 节流上报（见下）
   - `art.on('video:ended', ...)` — 标记已看 + 提示下一集
   - `art.on('destroy', ...)` — 清理引用

**进度上报节流逻辑**（在 `timeupdate` 事件中）：
```
const now = Date.now()
if (now - lastReportTime < 10000) return  // 不足 10 秒，跳过
lastReportTime = now
const position = Math.floor(art.currentTime)
const duration = Math.floor(art.duration) || 0
const watched = duration > 0 && (position / duration) >= 0.9
reportProgress(epId.value, position, watched)
```

**`video:ended` 事件处理**：
1. 调用 `reportProgress(epId.value, Math.floor(art.duration), true)` — 标记已看
2. 如果有下一集，显示提示 "即将播放下一集..."（可选：3 秒倒计时后自动跳转，或显示 "播放下一集" 按钮手动点击）
3. 建议实现：显示一个覆盖层按钮 "播放下一集"，点击后 `router.replace` 到下一集路由

**`onBeforeUnmount`**：
1. 上报最终进度：`reportProgress(epId.value, Math.floor(art?.currentTime || 0), false)`
2. 销毁播放器：`art?.destroy()`

**切换集数**：
- 当 `epId` 变化时（用户点击集数列表或上/下一集按钮）
- `watch(epId)` 触发：先 `art?.destroy()`，重新加载数据和初始化播放器

#### 4.6.4 集数列表项展示

每个集数项显示：
- 集数编号（"第 N 话"）
- 已看标记：如果有该集的进度且 `watched === true`，显示 "✓"（绿色）
- 进行中标记：如果有进度但 `watched === false` 且 `position > 0`，显示 "●"（黄色）
- 当前播放集高亮（添加 CSS class）
- 点击跳转：`router.replace({ name: 'watch', params: { id: animeId, epId: episode.id } })`

> 需要在加载页面时同时请求 `getAnimeProgress(animeId)` 获取所有集的进度，用于集数列表显示标记。或者在切换集数时单独请求 `getProgress(epId)`，集数列表的标记只显示当前集的。推荐方案：页面加载时请求 `getAnimeProgress(animeId)` 一次，存储为 `Map<episodeId, EpisodeProgress>`，后续切换集数时更新对应项。

## 7. 注意事项

### 7.1 视频流 token 验证

视频流接口 `/api/episodes/:id/stream` 注册在**公开路由区**（不在 `JWTAuth` 中间件下），由 handler 内部解析 query param 中的 token。这是必须的，因为浏览器 `<video>` 标签请求不会携带 `Authorization` 头。

其余 3 个进度接口正常放在 `protected` 组下，通过 `JWTAuth` 中间件鉴权。

### 7.2 视频格式兼容性

测试文件是 MKV + HEVC 编码。浏览器原生 `<video>` 标签对 MKV/HEVC 的支持取决于浏览器和操作系统：
- Chrome/Edge on Windows：通常支持 HEVC（需硬件解码或扩展）
- Firefox：可能不支持 HEVC
- Safari：支持较好

如果浏览器无法解码，ArtPlayer 会触发 `error` 事件。这不是代码问题，而是格式兼容性限制。验收时如果当前浏览器无法播放 MKV/HEVC，可以用一个 MP4/H.264 文件测试，或确认 ArtPlayer 显示了适当的错误提示。

### 7.3 进度上报频率

`timeupdate` 事件触发频率很高（每秒约 4 次），必须节流。文档中设计的 10 秒间隔是合理的：太频繁会增加服务器负担，太稀疏会丢失进度。页面卸载时额外上报一次最终位置。

### 7.4 UPSERT 语法

SQLite 的 `ON CONFLICT ... DO UPDATE` 语法需要 SQLite 3.24+。`modernc.org/sqlite` 内嵌的 SQLite 版本满足此要求。唯一索引 `idx_watch_progress_user_episode` 是 UPSERT 的前提。

### 7.5 `ListAnimes` 签名变更影响

`ListAnimes` 增加 `userID` 参数会影响：
- `handlers/anime.go` 的 `List` handler — 需从 `middleware.CurrentUserID(c)` 获取 userID 传入
- `database/anime_test.go` 的 `TestListAnimesReturnsTotal` — 需传入测试 userID（可用 `1`）

### 7.6 集数列表进度刷新

扫描文件会删除并重建 episodes（`ReplaceEpisodes`），由于 `watch_progress` 表对 `episode_id` 有 `ON DELETE CASCADE` 外键，旧的进度记录会随之删除。所以扫描后集数列表的进度标记会清空，这是正确行为。

### 7.7 ArtPlayer 实例管理

- 切换集数时必须先 `art.destroy()` 销毁旧实例，再创建新实例
- `onBeforeUnmount` 必须销毁实例，防止内存泄漏
- ArtPlayer 的 `container` 需要是一个 DOM 元素，用 Vue 的 `ref` 获取

### 7.8 不要做的事

- **不要**实现服务器转码（需求文档明确要求直接播放原片）
- **不要**修改数据库表结构（表已在阶段一建好）
- **不要**配置 Nginx（阶段五）
- **不要**实现下载管理（需求文档明确不做）
- **不要**安装其他播放器库（ArtPlayer 已满足需求）
