# fan-web 文档

本目录同时容纳与当前 `main` 分支一致的长期文档，以及开发过程中需要的阶段计划、执行交接和验收记录。

## 文档索引

- [服务器端开发指南](开发指南.md)：Go 后端、Vue 前端、配置、数据库、鉴权、媒体与构建说明。
- [移动端开发指南](移动端开发指南.md)：Flutter Android App 的架构、播放、缓存、进度同步与构建说明。
- [更新与发布指南](更新与发布指南.md)：GitHub Releases 更新协议、资产契约、双端更新流程和发布检查。
- [项目 README](../README.md)：面向使用者的功能介绍、快速开始、部署与下载入口。

## 阶段文档

可以按开发需要创建阶段性交接文档，用于固定范围、实现方案、验收标准、完成状态和必要的执行记录。维护时遵守以下规则：

- 阶段工作改变了系统行为、接口、配置、构建方式或发布契约时，完成前必须把长期有效的结论同步到对应指南。
- 交接文档不能成为当前系统事实的唯一来源；长期开发者应能仅通过上面的长期文档理解现状。
- 阶段文档完成使命后，根据后续协作价值决定保留或清理，不强制永久保存，也不强制立即删除。

## 历史记录

历史变更和阶段完成情况分别由以下位置承担：

- 代码演进：Git 提交历史。
- 版本产物与用户可见变更：GitHub Releases。
- 待办、讨论与审查：GitHub Issue / Pull Request，或对应协作系统。

## 维护要求

- 代码行为、接口、配置、构建方式或发布契约变化时，同一改动中同步更新对应文档。
- 文档描述当前行为，避免同时保留多套互相冲突的流程。
- 阶段文档可以记录执行者、日期、提交哈希和验收输出；同步到长期文档时只提炼当前仍有效的事实与约束。
- 不记录密码、JWT 密钥、keystore 内容、`key.properties` 内容或其他凭据。
- 发布命令以 `.opencode/skills/publish-release/SKILL.md` 为准；本目录只维护稳定契约和必要解释。
