# fan-web 移动端开发指南

本文件面向后续接手移动端的开发者（含 AI 助手），帮助快速理解 Flutter App 的项目结构、核心流程与常见注意点。文档总览见 [文档索引](README.md)，服务器端部分见 [服务器端开发指南](开发指南.md)，更新协议与发版流程见 [更新与发布指南](更新与发布指南.md)。

## 一、项目概况

fan-web 移动端是一个 **Flutter Android App**，位于仓库 `mobile/` 目录，目标是替代手机浏览器看番，提供原生播放体验。后端零改动，完全复用现有 REST API。

- **框架**：Flutter 3.x（Dart）
- **播放器**：media_kit（libmpv 内核），对 mkv/HEVC 10bit/内封字幕轨道支持最好
- **网络**：dio（拦截器注入 JWT、统一处理 `{code, message, data}` 响应包装与 401）
- **状态管理**：Riverpod（NotifierProvider + autoDispose）
- **路由**：go_router
- **本地存储**：SharedPreferences（token、服务器地址、用户快照、番剧缓存、进度 outbox）
- **亮度**：screen_brightness
- **音量**：volume_controller（控制系统媒体音量）
- **图片缓存**：cached_network_image

## 三、核心流程

### 3.1 认证闭环

1. **登录**（`ServerLoginScreen`）：输入服务器地址 + 用户名密码 -> `AuthApi.login` -> token 存 SharedPreferences -> 路由跳转列表页
2. **会话恢复**（`AuthNotifier._restoreSession`）：App 启动时读 token -> 调 `/api/auth/me` 验证
   - 成功：进入已认证状态，并 `unawaited(outbox.syncAll)`
   - **网络错误**（连接超时/连接失败）：保留 token，进入**降级状态**（`isSessionDegraded=true`），使用本地用户快照显示已登录但离线；**降级路径不同步 outbox**
   - **认证失败**（401/业务码 2001）：清 token，回登录页
   - **登录成功**后同样 `unawaited(outbox.syncAll)`
3. **401 处理**：`ApiClient` 拦截器收到 401 或 code=2001 -> 调 `onUnauthorized` -> 清 token -> 路由自动跳登录页
4. **登出**（`UserSheet`）：确认对话框 -> 调 `/api/auth/logout` -> 清 token、用户快照、番剧缓存、进度 outbox -> 回登录页
5. **App 回前台**（`main.dart` 的 `WidgetsBindingObserver`）：若降级状态则调 `retrySession()`，同时触发 outbox 同步

### 3.2 番剧列表与缓存

- **缓存隔离**：缓存键为 `anime_list_cache_v2_{base64(serverUrl)}_{userId}`，按服务器和用户隔离
- **加载流程**：先读缓存立即显示 -> 后台请求网络更新 -> 成功后覆盖缓存
- **错误拆分**：`error`（首屏全量失败，显示错误页）、`refreshError`（有缓存但后台刷新失败，顶部提示）、`loadMoreError`（加载更多失败，底部重试按钮）

### 3.3 播放器

- **初始化**：先 `await outbox.syncAll()` 同步待上传进度 -> 查询断点 -> `player.open(Media(streamUrl))` -> 等 duration -> seek 到断点 -> 播放
- **视频流 URL**：先通过 dio Bearer 请求当前集的短期媒体票据，再由 media_kit 直接打开 `...?media_token={mediaToken}`。`MediaTokenResult.expiresAt` 由 notifier 持久化，`buildPlayerMedia` 不得丢弃。过期前 5 分钟预刷新；刷新进行中或临近过期时 `_handleError` 忽略并尝试 reopen。打开失败且距过期 60 秒内只做一次 refresh+reopen。`MediaTokenUnsupported` 硬失败。App 只使用 `media_token`，不再回退 `?token=`。
- **字幕**：通过 `player.state.tracks` 枚举内封字幕轨道（libmpv 原生解析），默认选中首条。字号三档 20/24/28，默认 20。`seek` / `setSubtitleTrack` **不得**写入 `state.error`，只通过 `player_screen.dart` 现有 `ref.listen` 以 SnackBar 提示。
- **手势**：水平拖动快进/快退、右侧上下滑音量（控制系统媒体音量）、左侧上下滑亮度、双击暂停、单击显隐控制层
- **断点续播**：`_confirmResumePosition` 等待原生起播定位后再有限 seek 兜底。恢复失败时保留原来的正进度哨兵（`_origSaved`），不得清零后用 0 覆盖服务端断点。
- **进度上报**：每 15 秒定时 + 暂停/退出/播放完成时。`shouldQueueProgress(position)` 在 `<1` 秒时为 false；dispose 不得 `queue(0)`。先 `await outbox.save(record)` 立即落盘 -> 网络发送放入串行 Future 链 -> 成功后 `outbox.removeIfMatched`
- **90% 阈值**：position/duration >= 0.9 标记 watched（与 Web 端一致）

### 3.4 进度 Outbox

`ProgressOutbox`（`services/progress_outbox.dart`）确保断网时进度不丢失：

- **身份键**：`{serverUrl}|{userId}|{episodeId}`，按服务器和用户隔离
- **合并规则**：同一集只保留最新 position，watched 取逻辑或（不可降级）
- **串行化**：所有存储操作通过 `_storageChain` 串行，所有同步操作通过 `_syncChain` 串行，避免并发覆盖
- **时间戳保护**：`_isAtLeastAsNew()` 防止旧并发写入回滚新位置
- **触发时机**：进入播放器前、退出播放器后、App 回前台、**成功**会话恢复后、**登录成功**后。降级会话不同步。
- **失败分类**：`syncAll` 对失败做分类处理——业务码 1002（该集已被服务端删除）属永久失败，丢弃对应记录并继续同步其余；其余错误（网络类、401 由 `ApiClient.onUnauthorized` 统一走重新登录、5xx、9999、未知异常）一律**停止本轮同步**并保留剩余记录等下次重试，避免网络故障时请求风暴、避免播放器初始化被逐条超时阻塞数分钟。

### 3.5 应用更新

- 用户在 `UserSheet` 主动点击检查更新，`app_updater.dart` 请求 GitHub Releases 的 `latest` 接口；不做启动时强制检查、后台下载或强制更新。
- 只有最新 tag 高于 `appVersion` 且该 Release 包含 `fan-web-app-*.apk` 时才提示移动端更新。纯服务器 Release 不会触发 App 更新。
- 用户确认后用 dio 下载 APK 到 `getTemporaryDirectory()`，对话框显示进度并允许取消；下载失败时删除不完整文件。
- 下载完成后先做完整性校验：`sha256sumsUrl` **非空**时，获取失败或缺少本 APK 行必须失败并删除 APK；URL 为 null/空时只做 size 校验。然后由 `open_filex` 调起 Android 系统安装器。Manifest 需要 `REQUEST_INSTALL_PACKAGES`，不需要外部存储写权限。
- 双端资产约定、版本同步和发布验证见 [更新与发布指南](更新与发布指南.md)。

## 五、构建与测试

### 5.1 开发环境

```bash
export PATH="$HOME/Android/Sdk/platform-tools:$HOME/flutter/bin:$PATH"
export FLUTTER_STORAGE_BASE_URL="https://storage.flutter-io.cn"
cd mobile
flutter pub get
flutter analyze
NO_PROXY=127.0.0.1,localhost flutter test --no-pub
```

> `flutter test` 需清除代理环境变量，否则测试器 WebSocket 连接失败。

### 5.2 构建 APK

```bash
flutter build apk --release
```

APK 位于 `build/app/outputs/flutter-apk/app-release.apk`。签名配置在 `android/app/build.gradle.kts` 中：有 `key.properties` 时用 release 签名，否则回退 debug 签名。

### 5.3 版本号与发布（发版必读）

移动端版本规范**必须遵守仓库根 `AGENTS.md` 的 R2**，完整流程见 [更新与发布指南](更新与发布指南.md)。关键点：

- **`mobile/pubspec.yaml` 的 `version: X.Y.Z+N`**：
  - `X.Y.Z` 与本次 Release 的 tag 一致（如 `v1.2.0` 对应 `1.2.0`）。
  - **`+N` 是 Android `versionCode`，每次发布必须递增（至少 +1）**。否则已安装用户无法通过系统安装器原地升级，表现为"应用未安装"。
- **`mobile/lib/widgets/user_sheet.dart` 的 `const appVersion = 'X.Y.Z'`** 必须与 `pubspec.yaml` 同步。App 内"检查更新"用它与 GitHub 最新 tag 比对，写死旧值会导致永远提示"有新版本"。
- 更新提示判定：移动端只在 Release 附带 `fan-web-app-*.apk` 时认为有更新（`lib/services/app_updater.dart`）。因此只发服务器版时 App 不弹更新。
- 正式 APK 必须使用 `mobile/android/app/fan-web-release.jks` 和 `mobile/android/key.properties` 配置的 release 签名；两者均为本地机密，不得提交。
- 缺少 `key.properties` 时 Gradle 会回退 debug 签名，仅用于本地构建，绝不能作为正式 Release 资产。

### 5.4 真机调试

手机开启无线调试（Android 11+），WSL 内连接：

```bash
adb pair <ip>:<pair_port>
adb connect <ip>:<connect_port>
flutter run
```

> 播放器相关功能必须真机验证，模拟器无硬件解码。

## 六、关键注意点

1. **播放器文件谨慎修改**：`player_screen.dart` 和 `player_provider.dart` 中的控制层计时、手势竞争、字幕位置等经过多轮真机调优，修改前务必充分理解现有逻辑。
2. **断点续播时序**：`_initialize()` 中必须先 `await outbox.syncAll()` 再查询断点，否则 outbox 中的旧进度可能覆盖服务端最新位置。
3. **outbox.save 必须立即执行**：不能放在 Future 链中，否则进程被杀死时最新进度未落盘。
4. **会话异常分类**：`_restoreSession` 中必须区分网络错误（进入降级）和认证错误（清 token）。`DioException` 按 `type` 和嵌套 `ApiException` 精确判断。
5. **缓存键无碰撞**：使用 `base64Url.encode(utf8.encode(serverUrl))` 而非正则替换，避免不同服务器地址产生相同键。
6. **`flutter analyze` 中的 const 陷阱**：`TextTheme`、`DividerThemeData` 等 const 构造函数中不能调用方法（如 `withValues`），需用 `static final` 变量预先计算。

## 七、开发与验证清单

- 改动状态管理：改 `providers/` 下的 Notifier，注意 `ref.watch` vs `ref.read` 的区别。
- 改动 API：改 `api/` 下的类，注意视频流 URL 不走 dio。
- 改动播放器：**谨慎**，充分理解手势竞争和字幕位置逻辑后再改。真机验证必须。
- 改动主题：改 `theme/app_theme.dart`，色彩对齐 Web 端 `MASTER.md`。
- 补充测试：纯逻辑测试放 `test/`，使用 `ProviderContainer` + `overrideWithValue` 测试有依赖的类。
- 交付前：`flutter analyze` 无 error + `flutter test` 全通过 + `flutter build apk --release` 成功。
