# 看番网站需求文档

## 1. 项目概述

搭建一个私人番剧在线观看网站，供个人和朋友使用，不对公众开放。番剧通过 qBittorrent 下载，网站不集成下载管理功能，仅负责番剧展示与在线播放。

- **部署环境**：VPS 2核 2G
- **开发环境**：WSL (Ubuntu 20.04)
- **使用规模**：2-5 人，低并发

## 2. 核心约束

| 约束项 | 说明 |
|--------|------|
| 服务器资源 | 2核 2G，技术栈必须轻量，内存占用尽量低 |
| 视频播放 | 直接播放原片，**不做服务器转码**，靠客户端解码 |
| 下载流程 | 在 qBittorrent 中手动提交下载，完成后由网站管理文件关联 |
| 不对公众开放 | 需要登录认证，仅限受邀用户 |

## 3. 技术选型

### 3.1 选型原则

在 2核2G 约束下，优先选择 **低内存占用、编译型、单二进制部署** 的方案，避免运行时环境开销。

### 3.2 技术栈

| 层级 | 选型 | 理由 |
|------|------|------|
| 后端 | **Go (Gin)** | 编译为单二进制，运行时内存极低（~20MB），并发性能强，适合低配 VPS |
| 前端 | **Vue 3 + Vite** | 构建后为纯静态文件，由后端直接托管，无 Node 运行时开销 |
| 数据库 | **SQLite** | 嵌入式数据库，零额外进程开销，单文件存储，2-5人使用完全够用 |
| 视频服务 | **Nginx（反向代理 + 静态文件）** | Nginx 原生支持 HTTP Range 请求（206），高效处理视频拖拽进度条，Go 后端不直接处理大文件传输 |
| 元数据源 | **Bangumi API** | 获取番剧封面、简介、集数等信息 |

### 3.3 为什么不选其他方案

- **不选 Java/Spring**：JVM 内存占用大，2G 机器跑不起
- **不选 Python/Flask**：运行时性能弱，内存占用比 Go 高
- **不选 Node.js**：有运行时开销，单线程模型在 2核机器上浪费
- **不选 MySQL/PostgreSQL**：需要额外进程，占用 100-300MB 内存，SQLite 足够
- **不选 Plex/Jellyfin**：偏重，自带转码功能浪费资源，且定制性差

### 3.4 部署架构

```
用户浏览器
    │
    ▼
┌──────────────────────────┐
│        Nginx (443)        │
│  ┌────────────────────┐   │
│  │ /api/*  → Go 后端   │   │    ┌──────────┐
│  │          (Gin)      │──────▶│ SQLite   │
│  │ /video/* → 静态文件  │   │    │ (单文件)  │
│  │ /*      → 前端静态   │   │    └──────────┘
│  └────────────────────┘   │
│                           │
│  视频文件目录 (只读挂载)    │
│  /data/anime/...          │
└──────────────────────────┘
```

- Nginx 监听 443（HTTPS），统一入口
- `/api/*` 反代到 Go 后端（监听本地端口如 :8080）
- `/video/*` 直接由 Nginx 提供静态文件服务，带 Range 支持
- `/*` 返回 Vue 构建的静态文件

## 4. 功能需求

### 4.1 用户认证

| 编号 | 功能 | 说明 |
|------|------|------|
| U-01 | 登录 | 用户名 + 密码登录，返回 JWT Token |
| U-02 | 登出 | 清除 Token |
| U-03 | 访问控制 | 除登录接口外，所有接口需携带有效 Token |
| U-04 | 用户管理 | 管理员可添加/删除用户（仅管理后台，无注册功能） |

**设计说明**：不做注册，用户由管理员手动创建。Token 有效期可设为 7 天，前端存储在 localStorage。

### 4.2 番剧管理

| 编号 | 功能 | 说明 |
|------|------|------|
| A-01 | 番剧列表 | 展示所有已入库番剧，以封面卡片形式展示，支持分页 |
| A-02 | 搜索 | 按标题搜索番剧 |
| A-03 | 番剧详情 | 展示封面、标题、简介、集数列表、播放状态 |
| A-04 | 添加番剧 | 输入 Bangumi ID 或搜索标题，拉取元数据入库 |
| A-05 | 编辑番剧 | 修改标题、简介、封面等信息 |
| A-06 | 删除番剧 | 从库中移除番剧记录（可选是否同时删除文件） |
| A-07 | 集数管理 | 手动指定番剧的集数数量，关联视频文件 |

**添加番剧流程**：
1. 用户在 qBittorrent 下载好番剧
2. 在网站中通过 Bangumi 搜索/ID 添加番剧元数据
3. 将下载的视频文件目录关联到该番剧
4. 系统自动扫描目录下的视频文件，按文件名识别集数并关联

### 4.3 视频播放

| 编号 | 功能 | 说明 |
|------|------|------|
| V-01 | 在线播放 | 浏览器内嵌播放器，直接播放原片 |
| V-02 | 进度拖拽 | 支持拖拽进度条，通过 HTTP Range 请求实现 |
| V-03 | 播放记忆 | 记录每个用户每集的播放进度，下次继续播放 |
| V-04 | 倍速播放 | 支持 0.5x / 1x / 1.25x / 1.5x / 2x |
| V-05 | 全屏 | 支持全屏播放 |
| V-06 | 格式支持 | 优先支持 MP4/MKV，取决于浏览器解码能力 |

**播放器选型**：使用 [ArtPlayer](https://artplayer.org/) 或 [DPlayer](https://dplayer.js.org/)，轻量且支持所需功能。

**播放地址规则**：视频文件通过 Nginx 静态服务提供，URL 形如 `/video/{anime_id}/{episode}/{filename}`，前端播放器直接使用该 URL 作为 `src`。

### 4.4 播放进度

| 编号 | 功能 | 说明 |
|------|------|------|
| P-01 | 自动记录 | 播放时定时（每 10 秒）上报当前播放位置 |
| P-02 | 继续播放 | 重新打开同一集时，从上次位置继续 |
| P-03 | 已看标记 | 播放进度 > 90% 标记为已观看，在集数列表中显示 |
| P-04 | 番剧进度 | 在番剧列表/详情中展示观看进度（如 5/12） |

## 5. 数据模型

### 5.1 数据表设计

```
users
├── id          INTEGER PRIMARY KEY
├── username    TEXT UNIQUE NOT NULL
├── password    TEXT NOT NULL          -- bcrypt 哈希
├── is_admin    BOOLEAN DEFAULT FALSE
└── created_at  DATETIME DEFAULT CURRENT_TIMESTAMP

animes
├── id          INTEGER PRIMARY KEY
├── title       TEXT NOT NULL          -- 主标题
├── title_cn    TEXT                   -- 中文标题
├── bangumi_id  INTEGER                -- Bangumi 条目 ID
├── cover       TEXT                   -- 封面图 URL 或本地路径
├── summary     TEXT                   -- 简介
├── ep_count    INTEGER DEFAULT 0      -- 总集数
├── file_path   TEXT                   -- 视频文件根目录路径
└── created_at  DATETIME DEFAULT CURRENT_TIMESTAMP

episodes
├── id          INTEGER PRIMARY KEY
├── anime_id    INTEGER NOT NULL       -- 关联番剧
├── ep_number   INTEGER NOT NULL       -- 集数编号
├── title       TEXT                   -- 单集标题（可选）
├── file_path   TEXT NOT NULL          -- 视频文件相对路径
├── duration    INTEGER                -- 时长（秒）
└── FOREIGN KEY (anime_id) REFERENCES animes(id)

watch_progress
├── id          INTEGER PRIMARY KEY
├── user_id     INTEGER NOT NULL
├── episode_id  INTEGER NOT NULL
├── position    INTEGER DEFAULT 0      -- 播放位置（秒）
├── watched     BOOLEAN DEFAULT FALSE  -- 是否已看完
├── updated_at  DATETIME
└── FOREIGN KEY (user_id) REFERENCES users(id)
└── FOREIGN KEY (episode_id) REFERENCES episodes(id)
```

## 6. 接口设计

### 6.1 认证

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/login` | 登录，返回 JWT |
| POST | `/api/auth/logout` | 登出 |
| GET | `/api/auth/me` | 获取当前用户信息 |

### 6.2 番剧

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/animes` | 番剧列表（分页、搜索） |
| GET | `/api/animes/:id` | 番剧详情 |
| POST | `/api/animes` | 添加番剧 |
| PUT | `/api/animes/:id` | 编辑番剧 |
| DELETE | `/api/animes/:id` | 删除番剧 |
| POST | `/api/animes/:id/scan` | 扫描文件目录，关联集数 |
| GET | `/api/animes/:id/episodes` | 获取番剧的集数列表 |

### 6.3 播放进度

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/progress/:episode_id` | 获取某集播放进度 |
| POST | `/api/progress/:episode_id` | 上报播放进度 |
| GET | `/api/progress/anime/:anime_id` | 获取某番剧所有集的播放进度 |

### 6.4 管理员

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/users` | 用户列表 |
| POST | `/api/admin/users` | 创建用户 |
| DELETE | `/api/admin/users/:id` | 删除用户 |

### 6.5 Bangumi 搜索

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/bangumi/search?keyword=` | 搜索番剧 |
| GET | `/api/bangumi/subject/:id` | 获取条目详情 |

## 7. 非功能需求

| 项目 | 要求 |
|------|------|
| 内存占用 | Go 后端 < 50MB，Nginx < 10MB，总系统占用 < 500MB |
| 响应时间 | API 响应 < 200ms（不含外部 API 调用） |
| 并发 | 支持至少 3 个同时在线播放（受限于带宽） |
| HTTPS | 部署时使用 Let's Encrypt 证书 |
| 安全 | 登录限速（5次/分钟），JWT 鉴权，视频路径不可遍历 |
| 备份 | SQLite 单文件，定期 cron 备份 |

## 9. 开发计划

- Go 项目初始化，Gin 路由框架搭建

- 用户认证（登录、JWT 中间件）
- Vue 项目初始化，基础布局，路由

### 阶段二：核心功能
- Bangumi API 对接（搜索、获取详情）

### 阶段三：完善与部署
- 用户管理后台
- 前端 UI 完善（响应式、移动端适配）
- Nginx 配置与 HTTPS
- VPS 部署

## 10. 部署方案

### 10.1 VPS 部署

```bash
# 1. 编译后端（交叉编译为 Linux amd64）
CGO_ENABLED=1 GOOS=linux GOARCH=amd64 go build -o fan-web ./backend/

# 2. 构建前端
cd frontend && npm run build

# 3. 上传到 VPS
# - fan-web 二进制
# - frontend/dist 静态文件
# - nginx.conf

# 4. VPS 上运行
# - 用 systemd 管理 Go 后端进程
# - Nginx 配置反向代理 + 静态文件服务
# - Let's Encrypt 配置 HTTPS
```

### 10.2 systemd 服务配置

```ini
[Unit]
Description=Fan-Web Backend
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/fan-web
ExecStart=/opt/fan-web/fan-web --port 8080
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
