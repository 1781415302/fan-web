# 看番网站 - 整体开发计划

## 概述

基于需求文档，将开发过程拆分为 **6 个阶段**，每个阶段产出可独立运行和测试的成果。每个阶段编写一份详细交接文档，交付给其他 AI 实现。

## 阶段划分原则

- **按功能域划分**：每个阶段是一个完整的功能域（认证、番剧管理、播放等），而非按前后端拆分，这样每阶段产出的功能可端到端测试
- **前后端同阶段交付**：同一功能的后端 API 和前端页面在同一阶段完成，避免接口联调的跨阶段依赖
- **前一阶段是后一阶段的前置条件**：阶段间有明确依赖顺序，但每阶段交付时系统处于可运行状态
- **每阶段交接文档自包含**：包含该阶段所需的全部信息（接口定义、数据模型、UI 描述、验收标准），接手 AI 无需翻阅其他文档即可开发

## 阶段一：项目搭建与基础设施

**目标**：搭建前后端项目骨架，初始化数据库，完成基础布局，系统可启动运行。

**后端**：
- Go + Gin 项目初始化，目录结构搭建
- SQLite 连接，建表（全部 4 张表）
- 配置文件加载（YAML：端口、数据库路径、视频根目录、JWT 密钥等）
- 统一响应格式封装（成功/错误 JSON 结构）
- 健康检查接口 `GET /api/health`
- 初始化管理员账号（首次启动自动创建，配置文件指定用户名密码）

**前端**：
- Vue 3 + Vite + TypeScript 项目初始化
- Pinia 状态管理、Vue Router 搭建
- Axios 封装（统一 baseURL、错误拦截）
- 基础布局组件（顶部导航栏 + 内容区）
- 空首页占位

**交付物**：
- 前后端均可启动运行
- 访问前端页面能看到基础布局
- `GET /api/health` 返回正常
- 数据库文件创建成功，表结构就绪

**不包含**：登录功能、任何业务页面

---

## 阶段二：用户认证系统

**目标**：完成登录认证全链路，系统具备访问控制能力。

**后端**：
- `POST /api/auth/login`：用户名密码校验，返回 JWT
- `GET /api/auth/me`：根据 Token 返回当前用户信息
- `POST /api/auth/logout`：登出（前端清除 Token 即可，后端可选维护黑名单）
- JWT 鉴权中间件：除 `/api/auth/login` 和 `/api/health` 外所有接口需携带 Token
- `GET /api/admin/users`：管理员查看用户列表
- `POST /api/admin/users`：管理员创建用户
- `DELETE /api/admin/users/:id`：管理员删除用户
- 登录限速中间件（同 IP 5 次/分钟）

**前端**：
- 登录页（用户名 + 密码表单）
- Auth Store（Token 存储、登录/登出动作、当前用户状态）
- 路由守卫：未登录跳转登录页
- Axios 拦截器：自动携带 Token，401 自动跳转登录
- 用户管理页（仅管理员可见）：用户列表、创建用户、删除用户
- 顶部导航栏显示当前用户名 + 登出按钮

**前置条件**：阶段一完成（项目骨架、数据库、布局组件）

**交付物**：
- 可通过登录页登录系统
- 未登录访问任何页面会跳转登录页
- 管理员可在用户管理页创建/删除用户
- 普通用户无法访问管理页面

---

## 阶段三：番剧管理

**目标**：完成番剧的增删改查与文件关联，能在网站上浏览番剧库。

**后端**：
- Bangumi API 对接：
  - `GET /api/bangumi/search?keyword=`：代理搜索 Bangumi 番剧
  - `GET /api/bangumi/subject/:id`：获取 Bangumi 条目详情（标题、封面、简介、集数）
- 番剧 CRUD：
  - `GET /api/animes`：番剧列表（分页、按标题搜索）
  - `GET /api/animes/:id`：番剧详情
  - `POST /api/animes`：添加番剧（入参含 Bangumi ID，后端拉取元数据入库）
  - `PUT /api/animes/:id`：编辑番剧
  - `DELETE /api/animes/:id`：删除番剧（可选是否删除文件）
- 集数管理：
  - `POST /api/animes/:id/scan`：扫描番剧 `file_path` 目录，识别视频文件，按文件名正则匹配集数，写入 episodes 表
  - `GET /api/animes/:id/episodes`：获取番剧集数列表
- 封面图处理：Bangumi 封面 URL 下载到本地存储，通过 `/api/` 路径提供

**前端**：
- 番剧列表页：封面卡片网格，分页，搜索框
- 添加番剧弹窗/页面：搜索 Bangumi -> 选择条目 -> 填写本地文件目录 -> 提交
- 番剧详情页：封面、标题、简介、集数列表（每集显示编号和标题）
- 编辑番剧：修改标题、简介、文件目录
- 扫描文件按钮：触发后端扫描，展示扫描结果
- 删除番剧（带确认）

**前置条件**：阶段二完成（认证系统，路由守卫）

**交付物**：
- 能通过搜索 Bangumi 添加番剧到库中
- 能关联本地视频文件目录并扫描出集数
- 番剧列表页展示所有已入库番剧
- 番剧详情页展示元数据和集数列表

---

## 阶段四：视频播放与进度记录

**目标**：完成在线播放和播放进度追踪，核心观看体验可用。

**后端**：
- 播放进度接口：
  - `GET /api/progress/:episode_id`：获取当前用户某集播放进度
  - `POST /api/progress/:episode_id`：上报播放进度（position 秒数）
  - `GET /api/progress/anime/:anime_id`：获取当前用户某番剧所有集的进度
- 视频文件安全访问：后端提供接口返回视频文件的实际路径或生成签名 URL，防止路径遍历
- Nginx 配置：`/video/` 路径映射到视频文件目录，启用 Range 请求

**前端**：
- 视频播放器集成（ArtPlayer 或 DPlayer）：
  - 播放原片，src 指向 `/video/` 路径
  - 支持进度拖拽、倍速播放（0.5x~2x）、全屏
- 播放页面：番剧信息 + 播放器 + 集数切换列表
- 播放进度上报：播放时每 10 秒上报当前位置
- 继续播放：打开已看过的集数时，提示并跳转到上次位置
- 已看标记：集数列表中已观看（>90%）的集显示标记
- 番剧观看进度：列表和详情页显示进度（如 5/12）

**前置条件**：阶段三完成（番剧数据、集数数据）

**交付物**：
- 能在浏览器中播放番剧视频
- 进度条可拖拽，倍速可切换
- 播放进度自动保存，重新打开可继续
- 集数列表有已看/未看状态

## 阶段五：自动入库与 UI 优化

**目标**：视频目录变动自动同步到番剧库（新番剧自动匹配 Bangumi 入库、目录删除自动清理、新剧集自动追加），并整体美化前端界面。

**后端**：
- Watcher 后台协程：定时轮询 `video.root_path`
- 新目录发现：解析目录名 → 搜索 Bangumi → 精确匹配自动入库，否则进入待匹配队列
- 待匹配队列：新表 `pending_animes`，前端确认/忽略/移除
- 目录消失检测：自动删除对应番剧记录（级联清理集数与进度）
- 剧集增量同步：已有番剧目录新增/删除单集文件时自动增删集数记录
- 新增接口：待入库列表、确认入库、忽略、移除、手动扫描、扫描状态

**前端**：
- 库同步页（`/library`，管理员入口）：待入库卡片、确认/忽略/移除、立即扫描、扫描状态
- UI 优化：骨架屏、首页继续观看、卡片进度条、详情页集数网格、公共样式抽取

**前置条件**：阶段四完成（番剧数据、集数数据、扫描与路径解析能力）

**详细设计**：见 `docs/阶段五交接文档.md`

**交付物**：
- 新建视频目录后自动出现在待入库列表或直接入库
- 删除目录后对应番剧自动从库中移除
- `/library` 页面可处理待匹配条目
- 全部页面视觉一致，无重复样式代码

## 阶段六：部署与完善

**目标**：完成生产部署所需的一切配置，系统可上线 VPS。

**部署配置**：
- Nginx 完整配置：HTTPS、反代后端、视频静态服务、前端静态托管
- systemd service 文件：Go 后端进程管理
- Let's Encrypt 证书配置（Certbot）
- Go 交叉编译脚本：`CGO_ENABLED=1` 编译 Linux amd64 二进制
- 前端构建脚本：`npm run build` 产物部署
- SQLite 定时备份脚本（cron + cp / .dump）

**功能完善**：
- 移动端响应式适配（番剧列表、播放器、导航栏）
- 错误页面与提示优化（404、网络错误、视频加载失败）
- 加载状态与骨架屏
- 空状态展示（无番剧、无搜索结果）

**前置条件**：阶段五完成（自动入库与 UI 优化）

**交付物**：
- 完整的部署文档和脚本
- Nginx 配置可直接使用
- VPS 上一键部署后系统可用
- 移动端可正常浏览和播放

## 时间预估

| 阶段 | 预估工作量 | 说明 |
|------|-----------|------|
| 阶段一 | 中 | 主要是搭骨架，无复杂业务逻辑 |
| 阶段二 | 低 | 认证是成熟模式，实现直接 |
| 阶段三 | 高 | Bangumi 对接 + 文件扫描正则，是业务核心 |
| 阶段四 | 中高 | 播放器集成和进度逻辑有一定复杂度 |
| 阶段五 | 中高 | Watcher 匹配逻辑 + 前端新页面与整体美化 |
| 阶段六 | 中 | 部署配置 + 移动端适配 |

## 交接文档说明

每个阶段的交接文档将包含以下内容：

1. **阶段目标**：本阶段要完成什么
2. **前置条件**：上一阶段交付了什么，当前系统状态
3. **技术约定**：目录结构、命名规范、响应格式等（阶段一确立，后续继承）
4. **后端详细设计**：接口定义（入参、出参、错误码）、数据模型变更、业务逻辑
5. **前端详细设计**：页面结构、组件划分、交互流程、UI 描述
6. **验收标准**：可逐条勾选的验收项
7. **注意事项**：踩坑提示、技术选型理由、安全注意点
