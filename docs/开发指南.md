# fan-web 服务器端开发指南

本文件面向后续接手本项目的开发者（含 AI 助手），帮助快速理解后端与前端的项目结构、核心流程与常见注意点。文档总览见 [文档索引](README.md)，移动端部分见 [移动端开发指南](移动端开发指南.md)，更新协议与发版流程见 [更新与发布指南](更新与发布指南.md)。

## 一、项目概况

**fan-web** 是一个自托管的个人看番（动漫）网站：将本地番剧视频目录自动扫描入库，提供番剧管理、在线播放、内封字幕、观看进度记录与用户认证。前后端一体化编译，最终交付为**单个无依赖的可执行文件**。

- **后端**：Go 1.21 + Gin + SQLite（`modernc.org/sqlite`，纯 Go 无 CGO）+ JWT + bcrypt
- **前端**：Vue 3 + Vite + TypeScript + Pinia + vue-router + ArtPlayer

与同类产品（Alist / Jellyfin）的差异化：**无需手动整理视频**（自动遍历识别集数 + 关联 Bangumi 自动建库）、**面向追番场景**（进度/续播/番组信息）、**极轻量**（常驻约 15MB）、**零配置部署**（首次运行 WebUI 引导）。

## 三、后端

### 3.1 配置（config/config.go）

`config.yaml` 字段与默认值：

| 字段 | 类型 | 含义 | 默认 |
|---|---|---|---|
| `server.port` | int | 监听端口（被占自动顺延） | 8080 |
| `server.mode` | string | Gin 模式 debug/release | debug |
| `database.path` | string | SQLite 文件路径 | `./data/fan-web.db` |
| `jwt.secret` | string | JWT 密钥（留空则首次初始化自动生成随机密钥） | 空 |
| `jwt.expire` | duration | 登录有效期 | 168h |
| `admin.username` | string | 初始管理员账号（**不保存明文密码**，密码只以数据库 bcrypt 哈希存在） | admin |
| `video.root_path` | string | 番剧视频根目录 | ../anime |

关键逻辑：
- `Load(path)`：文件**不存在**时返回带默认值的配置，且 `cfg.Configured=false`。这**不等于**直接进入首次运行：`prepareConfiguredInstance` 会再查管理员数量。无管理员才是首次运行；已有管理员则拒绝以未初始化状态启动，要求恢复 `config.yaml`。
- `PreflightSave(path)`：在提交数据库变更前验证配置目录可写、可创建临时文件，让初始化尽早失败并保持可重试。
- `Save(path)`：在目标文件的同一目录创建唯一隐藏临时文件，以 `0o600` 权限完整写入并 `Sync`，关闭成功后通过 `Rename` 原子替换。任一环节失败都会清理临时文件并保留旧配置。
- `JWTConfig.UnmarshalYAML`：接受 `"168h"` 人类可读时长。

### 3.2 启动流程（main.go）

1. `config.Load("config.yaml")`（文件缺失时 `Configured=false`，是否允许初始化见 §3.7）
2. `flag.Parse()` - `-port` 覆盖配置端口（优先级最高，在 listen 前写入 `cfg.Server.Port`）
3. `gin.SetMode(cfg.Server.Mode)`
4. `database.Init(cfg.Database.Path)` 建库建表
5. `prepareConfiguredInstance(...)` 完成公开 JWT 密钥轮换、旧明文密码移除和空库兼容；保存或回滚异常时拒绝启动
6. 组装 service/handler，`LoginRateLimiter(5, time.Minute)`
7. `gin.New()` + 脱敏访问日志/Recovery + 全局 `CORS()` + 64 KiB JSON 请求体限制 + 可信代理 `127.0.0.1`
8. `/api` 分组挂 `RequireSetup`，注册全部路由
9. `r.NoRoute(serveFrontend)` 托管嵌入前端，SPA 回退 index.html
10. `listenWithFallback(port, 10)` 端口绑定（冲突顺延，最多 10 次）。**仅当实际绑定端口等于配置端口**（含 `-port` 覆盖后的值）才清理 `.old` / `.pre-migration.bak`；回退绑定保留二者并打日志，且不把回退端口写回配置。然后带 ReadHeader/Read/Idle/MaxHeaderBytes 边界的 `http.Server.Serve`；不设置 WriteTimeout

### 3.3 API 路由

**公开路由组**（仅过 RequireSetup）：`/api/health`、`/api/version`、`/api/setup/status`、`POST /api/setup`、`POST /api/auth/login`（限流）。视频和字幕路由也位于该组，但 handler 内必须按 Bearer、`media_token` 的固定优先级自行完成鉴权，不属于匿名接口。

**登录用户**（JWTAuth）：`/api/auth/{me,logout}`、`GET /api/progress/continue`（必须注册在 `GET/POST /api/progress/:episode_id` **之前**，否则 Gin 会把 `continue` 当成 `episode_id`）、`GET/POST /api/progress/:episode_id`、`GET /api/progress/anime/:anime_id`、`/api/animes`（GET list/detail/episodes/cover）、`POST /api/episodes/:id/media-token`、`GET/PUT/DELETE /api/me/bangumi`、`POST /api/me/bangumi/sync`。

**媒体资源**（Bearer 或 `media_token`）：`GET /api/episodes/:id/stream` 与 `GET /api/episodes/:id/subtitles` 只接受 `Authorization: Bearer` 与 `?media_token=`。

**管理员**（JWTAuth + RequireAdmin）：番剧写操作（POST/PUT/DELETE `/api/animes*`、`POST /api/animes/:id/scan`、`POST /api/animes/:id/rebind`）、全库扫描作业（`POST /api/library/scan` 启动、`GET /api/library/scan` 轮询，**禁止再按同步 600s**）、`GET /api/library/unidentified`、`GET /api/library/dirs`、`/api/bangumi/**`、`/api/admin/users`、`GET /api/admin/update/check`、`POST /api/admin/update/perform`。单番 `POST /api/animes/:id/scan` 仍同步，Web `scanAnime` 可保留 600s 超时。

### 3.4 Middleware

- **CORS**：仅放行 `localhost:5173` / `127.0.0.1:5173`，携带 Authorization 头与凭据。
- **JWTAuth**：解析 `Authorization: Bearer <token>`，**校验对应用户仍存在**（用户已被删除则返回 2001 立即失效），再用数据库最新用户信息覆盖 claims 后写入 gin.Context；`RequireAdmin` 独立二次校验 `IsAdmin`。
- **RequireSetup**：`IsConfigured()==false` 时只放行 `/api/health`、`/api/setup/status`、`/api/setup`，其余返回"系统未初始化"。`IsConfigured` = `cfg.Configured` **或** `CountAdmins()>0`（查询失败按已配置处理，失败关闭）。中间件本身未改。`Submit` 已持有写锁，禁止再调 `IsConfigured()`：先看内存旗标，再 `CountAdmins`；旗标或 n>0 返回 2002，查询失败返回 9999「查询用户失败」。
- **LoginRateLimiter**：按客户端 IP 统计一分钟滑动窗口内的失败尝试（5 次/分钟），成功登录清空；来源表最多 4096 项。登录时 `ErrNoRows` 走 dummy bcrypt + 2003；其它 `GetUserByUsername` 错误返回 9999「查询用户失败」并 `rateLimiter.Reset(ClientIP)`，避免数据库故障把额度耗尽。无新登录码。
- **RequestLogger / Recovery**：只记录安全的 method/path/status/耗时和栈信息，不记录 query、请求头、请求体、响应体或 panic 值。
- **LimitJSONBody**：限制 POST/PUT/PATCH 请求体为 64 KiB。

### 3.5 Services（业务层）

- **auth**：`IssueToken` / `ParseToken`（登录 JWT）与 `IssueMediaToken` / `ParseMediaToken`（绑定用户和 episode 的 12 小时媒体票据）；两类 token 使用独立 Claims 和解析入口。
- **bangumi**：封装 `api.bgm.tv` 搜索与 Subject 详情（无 token 的 Search/GetSubject 保持原样），以及带个人 PAT 的 `/v0/me`、章节、收藏读写。含 User-Agent、超时、封面 https 化。不把 token 写进服务单例。`GetSubject` 另解析 infobox「别名」到 `Aliases`（`json:"-"`，不出站）。
- **bangumi_sync**：出站/入站「看过」布尔同步。`ReportProgress` 成功后异步入队 Drain，不阻塞 HTTP。详见 §3.13。
- **parser**：`ParseFilename` 纯函数，解析文件名->标题/集数/季号（`Season`，0=未知）。季号在剥离集数之前提取，标题规范为 `第{n}季`。集数识别含可选修订号：`[01v2]`、`Title-01v2.mkv` 为第 1 集；`[v2]`、`v2.mkv` 不是集数。扩展名模式用「非 v/数字」前缀（RE2 等价 lookbehind `(?<![vV\d])`）。另产出 `Kind=episode|movie`（`json:"-"`，出站省略）。T1a：`EpisodeNum>0` 一律 `episode`，即使文件名含「剧场版 / Movie」；电影的解析器 `EpisodeNum` 仍为 0。电影门闩：无 1–3 位集号，且（电影标记词，或 ASCII `[19xx]`/`[20xx]` + 强标题）。
- **scanner**：读目录生成剧集列表、`ListSubDirs`（一层、跳过 `.` 与 symlink；`GET /api/library/dirs` 接线，Web 添加页不接）、`HasVideoFiles`、`ResolveFilePath`（防路径穿越）、`ValidateRelativeVideoPath`。含 `SetRootPath`（初始化后动态更新）。`Scan` 先按文件名排序，再走 `ParseFilename` + `libraryEpisodeNum`（电影不再用裸 `extractEpisodeNumber` 决定是否入列）。真 `EpisodeNum>0` 先入列；电影在 1 空闲时规范为 `EpNumber` 1，第二部同号电影静默丢弃。`v2.mkv` 仍跳过。
- **library**：库扫描入库--遍历目录->解析文件名->按标题分组->`DecideBangumiMatch`（置信度 0.86 / 0.18，采用 `Winner.ID`）->建番剧/剧集。`normalizeTitle` **不再剥季号**；`itemMatchScore` 在 `querySeason>0` 且候选季不同时把分数封顶 0.85（无名候选视为 S1；`querySeason==1` 对无名候选不封顶；`querySeason==0` 不设闸）。含目录一致性校验、去重、未识别分类。`LibraryService.Scan` 仍同步、仍 `scanMu`、结果纯内存，**不写未识别表**。两遍标记：对每个视频（含已关联）`ParseFilename`，`EpisodeNum==1` 且 `Title!=""` 时按 `(relDir, Title)` 记「已有真集号 1」。`libraryEpisodeNum`：`Kind=movie` → 1，否则 `EpisodeNum`；**永不回写** `parsed.EpisodeNum`。同 `(relDir, Title)` 已有真集号 1 的电影视为规范集号 0 →「无法识别集数」。别名重打分仅当组内任一 `Kind=movie` 且第一轮 `DecideBangumiMatch` 未 Accept：对 top≤3 候选 `GetSubject`，再 `DecideBangumiMatchWithAliases`（同一 0.86 / 0.18）。纯 TV 组零次额外 `GetSubject`。宁漏不配。已知误伤：年+强标题 TV 如 `[Fansub][Bocchi the Rock!][2022][1080p].mkv` 会被标 `Kind=movie`（T1a 接受代价）。Search 空候选没有收件箱一键；手绑 = 添加番剧 + 详情 Scan。根目录 `DeleteUnidentifiedByDir("")` 会清全部根收件箱行——1.4 已知边，1.4.2 不修。
- **library_job**：进程内单槽全库扫描作业（`idle`/`running`/`done`/`error`）。`POST /api/library/scan` 启动或返回当前作业，`GET /api/library/scan` 读状态。已 running 不启第二趟。作业不落盘。详见 §3.10。
- **subtitles**：纯 Go 解析 MKV 容器（`ebml-go` + `go-mkvparse`），提取内封文本字幕轨道（SRT/ASS/SSA/WebVTT）并转为 VTT 格式供 Web 端使用。不依赖 ffmpeg 等外部工具。`decodeASSDialogue` 同时处理 `Dialogue:` 的 10 字段 SplitN 与 Matroska 无前缀 9 字段 CSV；字段不足时仍做 `\N`/`\n`/`\h` 与去标签，绝不返回原始 `{\an8}`，也不解析 CodecPrivate。
- **updater**：查询 GitHub 最新 Release，只在存在当前 `GOOS/GOARCH` 对应二进制时报告更新；执行更新时串行化并发请求、Windows 直接拒绝并引导手动替换。`HasStaleUpdateBackup()` 在 **TryLock / Windows 检查之后、下载之前** 若发现残留 `.old` 即返回 `errUpdateBackupExists`。校验资产大小和 `SHA256SUMS.txt`，以 `.new` / `.old` 完成替换；新版本**绑定到配置端口**后将 `.old` 晋升为 `.prev`。完整契约见 [更新与发布指南](更新与发布指南.md)。

### 3.6 数据库（database 包）

表结构（由版本化迁移维护，见 `migrations.go` / `migrations_v1.go`）：
- `users(id, username UNIQUE, password, is_admin, created_at)`
- `animes(id, title, title_cn, bangumi_id, cover, summary, ep_count, file_path, created_at)`
- `episodes(id, anime_id FK->animes ON DELETE CASCADE, ep_number, title, file_path, duration)`
- `watch_progress(id, user_id FK, episode_id FK, position, watched, updated_at)` + 唯一索引 `(user_id, episode_id)`
- `unidentified_files(id, file_path, file_name, reason, candidates, updated_at)` + UNIQUE `(file_path, file_name)`（v3）
- `user_bangumi_tokens(user_id PK FK->users ON DELETE CASCADE, access_token, updated_at)`（v3；明文存 0600 库，日志禁止打印完整 token）
- `bangumi_sync_outbox(id, user_id FK, episode_id FK, created_at)` + UNIQUE `(user_id, episode_id)`（v3；用户/剧集 CASCADE）
- `schema_migrations(version PK, name, applied_at)` 记录已应用迁移版本

PRAGMA：`journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`；`Init` 设 `SetMaxOpenConns(1)`。

**迁移机制**：`Init` 在 `Ping` 成功后调用 `runMigrations`。迁移必须从 v1 连续编号，按版本升序逐个在独立事务中执行并记录。数据库中的已应用记录必须是当前程序迁移列表的连续前缀，且版本名称一致；发现未知高版本、缺口或名称不匹配时拒绝启动，避免旧二进制静默打开新版数据库。新增表结构变化时，在 `backend/database/` 追加新版本，**不要修改已发布的版本 1**。

**v2 迁移（唯一索引）**：为 `animes(bangumi_id)`（部分索引 `bangumi_id > 0`）与 `episodes(anime_id, ep_number)` 建立唯一索引，作为库扫描并发写入的数据库层兜底。老库中已存在的重复行先按"保留最小 id"策略去重，绝不直接丢弃数据：重复番剧的剧集 reparent 到保留番剧；重复剧集的观看进度合并（position 取更大、watched 取或、updated_at 取更近）。若同一 `bangumi_id` 的重复番剧分布在不同目录（`file_path` 不同），合并会导致播放路径失效，迁移**直接拒绝并列出受影响记录**，需人工介入后重试。

**v3 迁移（`library_inbox_and_bangumi_sync`）**：新建未识别表、每用户 Bangumi PAT 表、同步 outbox。禁止改 v1/v2 SQL 文本。`UpdateAnime` 仍不写 `bangumi_id`；换绑走 `UpdateAnimeBangumi`（撞部分 UNIQUE 返回 `ErrBangumiBound`）。

**迁移前备份**：执行迁移前，`database.BackupDatabase` 先 `VACUUM INTO` 转义后的临时文件（`backupPath+".tmp"`），`chmod 0600`，再把已有 dest 改名为 sidecar，tmp 就位后再删 sidecar；任一步失败都把 dest 还原。dest 不在而 sidecar 在时先还原，不在入口删除 sidecar。连同自更新保留的 `<可执行文件>.old` 构成一套回滚资产。**仅当实际端口等于配置端口**才清理；回退绑定保留 `.old` 与 bak。

⚠️ **重要**：`InitAdmin` 仅在数据库中**尚无管理员**时创建（`COUNT(*) WHERE is_admin=1`）。因此已运行实例改 `config.yaml` 里的 `admin.*` **不会生效**，需改数据库或走管理接口。

⚠️ **观看状态不可逆**：`UpsertProgress(userID, episodeID, position, watched)` 无 duration 列。`watched = MAX(...)` 一旦已看不降级。`position`：`excluded.position=0 AND existing>0` 时保留原值，避免销毁瞬间的 0 哨兵覆盖断点；首次 INSERT 的 0 仍会写入。HTTP 仍是 `POST /api/progress/:episode_id`。签名与 CASE/MAX SQL **冻了**。入站 Bangumi 同步会 `UpsertProgress(..., 0, true)`，刷新被标看过行的 `updated_at`，这些番会顶到继续看前面；接受这个顺序。

**剧集重扫**：`database.SyncEpisodes` 以 `(anime_id, ep_number)` 为稳定业务键同步剧集——匹配到的集只更新字段、保留 ID 和观看进度；新增集插入；未出现的旧集删除。**空扫描保护**：已有剧集非空但本次扫描结果为空时拒绝同步并返回"未扫描到有效视频，已保留原有剧集"，防止目录临时不可用清空番剧。已有剧集和扫描结果都为空时允许成功。

**事务约束**：数据库 `SetMaxOpenConns(1)`。事务内部不得调用使用全局 `database.DB` 的现有函数，否则事务占用唯一连接会死锁；事务内查询写入必须全部使用同一个 `*sql.Tx`。新增数据库测试不要调用 `t.Parallel()`（共享包级 `database.DB`）。

### 3.7 首次运行 / 零配置初始化

三端协作：
1. **后端**：`config.Load` 读不到文件 -> `Configured=false`。若数据库已有管理员，启动直接拒绝（「配置文件缺失但数据库已有管理员…请恢复 config.yaml」）；`CountAdmins` 失败包装为「查询管理员数量失败」。文件存在时走原有 bootstrap。缺失文件且 0 个管理员才是首次运行。
2. **前端**：路由守卫调 `getSetupStatus()`，未初始化强制跳 `/setup`。
3. **初始化**（`SetupHandler.Submit`）：完整流程受同一把互斥锁保护。锁内**不要**再调 `IsConfigured()`：先看内存旗标，再 `CountAdmins`；已初始化返回 2002，查询失败返回 9999「查询用户失败」。随后校验参数 + 视频目录存在性 -> 配置写入预检（`PreflightSave`）-> `database.CreateUser(..., true)` 建管理员 -> 签发 token -> 原子写 `config.yaml` -> `SetRootPath` 动态更新 -> 整体成功后才提交内存状态。任何后续失败（签发 token、保存配置）都会按精确用户 ID 回滚删除刚创建的管理员，保证可原样重试。预检和保存均用 `os.CreateTemp` 在同目录创建唯一隐藏临时文件，保存通过 `Rename` 原子替换，进程中断不会留下半个 YAML。

### 3.8 封面代理

`GET /api/animes/:id/cover` 是受认证保护的封面代理接口。移动端无法直连 Bangumi CDN 时，由后端读取 `animes.cover` 并转发图片。安全边界如下：

- 只允许 `lain.bgm.tv` 和其他 `.bgm.tv` 子域，协议必须为 HTTP 或 HTTPS；每次重定向都会重新校验目标，最多跟随 3 次。
- 响应体最大 10 MiB，同时限制已声明长度和未知长度的流式响应。
- 只接受 JPEG、PNG、WebP、GIF；响应声明类型与内容探测类型必须一致，拒绝 SVG 等其他格式。
- 返回经规范化的图片类型，并设置 `X-Content-Type-Options: nosniff`。

### 3.9 鉴权中间件

`JWTAuth`：解析 `Authorization: Bearer <token>` 后**额外查询一次当前用户**。用户不存在（已被删除）立即返回 `2001`，使旧 token 在管理员删除用户后立刻失效；同时用数据库最新 `is_admin` 覆盖 claims，避免使用过期角色。`RequireAdmin` 独立二次校验管理员。

### 3.10 全库扫描作业与未识别表

v1.4 起全库扫描改为进程内作业，**禁止再按同步 600s** 处理。

- `POST /api/library/scan`：管理员，无 body。立即返回 `ScanJob`（`state` / `started_at` / `finished_at` / `error` / `result`）。idle/done/error 时开 goroutine 跑 `LibraryService.Scan` 并返回 `running`；已 `running` 返回当前快照，不启第二趟。
- `GET /api/library/scan`：读作业。从未扫过为 `idle`。作业只在内存，进程重启变 `idle`，未识别表仍在。
- 客户端：`POST` 后每 1s `GET` 直到 `done|error`；轮询走默认 10s 超时。15 分钟停轮询并提示仍在服务器执行。Web / App 都走这套。
- 单番 `POST /api/animes/:id/scan` 仍同步；Web `scanAnime` 可保留 600s 超时。

**未识别表 persist**。1.3 的未识别只活在当次扫描 JSON，关页面即丢。

- **成功全库扫描替换**：`LibraryJob` 在 `Scan` 返回 nil 后过滤已入库文件，再 `ReplaceUnidentified`（事务 DELETE 全表 + INSERT，空则清空）。这是唯一写替换的地方。Scan 失败或 panic 不改表。
- **单番 Scan 有剧集才按目录删**：仅当现有 Success 路径且 `len(storedEpisodes)>0` 才 `DeleteUnidentifiedByDir(anime.FilePath)`。0 集不删。删失败只打日志，仍返回 `{scanned,episodes}`。
- 读取：`GET /api/library/unidentified`（page/page_size，函数内夹紧）。确认未识别仍是 `POST /api/animes` 再 `POST /api/animes/:id/scan`；Create 抛 1001 则不 scan。

### 3.11 重绑定（仅 Web）

`PUT /api/animes/:id` 仍然不能改 `bangumi_id`。新管理动作 `POST /api/animes/:id/rebind` `{"bangumi_id":N}`：换元数据（title/title_cn/cover/summary/ep_count/bangumi_id），不改 `file_path`、不删剧集、不重扫。`N<=0` → 1001；番不存在 → 1002；另一番已绑 → 1001「该 Bangumi 条目已绑定其他番剧」。

UI 只做 Web 详情（`AnimeDetailView`，`v-if="isAdmin"` 隐藏，不 disable）。**手机不做重绑/编辑表单**。配错番回 Web 改。

### 3.12 继续看

`PickContinueEpisode` 与 Dart `pickContinueEpisode` **同序**：先第一集进行中（`!watched && position>0`），再第一集未看（`!watched`），全看完返回 nil、**不出现**。`position=0 && !watched` 不当进行中。episodes 必须已是 `ListEpisodesByAnimeID` 顺序（`ep_number ASC, id ASC`），Pick 不再排序。

`GET /api/progress/continue`（登录，limit 默认 20、夹 1..50）走 `ListContinueWatching`：有进度的番按 `max(wp.updated_at)` DESC，每番 Pick，nil 跳过。**App 列表顶用这条。Web Home 仍最近入库**，不接 continue。

入站 Bangumi 同步会顶 `updated_at`（见 §3.6）；SQL 冻了，接受。

### 3.13 Bangumi 个人 PAT 同步

每用户一枚个人 Access Token，存在 SQLite，永不进 JWT、永不完整回给客户端。令牌由用户在 https://next.bgm.tv/demo/access-token 自助签发。不接 OAuth。**只同步看过布尔，不同步秒数。**

- `GET /api/me/bangumi`：未绑 `{linked:false}`（省略 suffix）；已绑 `{linked:true, suffix:"末4字符"}`
- `PUT /api/me/bangumi`：先 `GET /v0/me` 校验。成功才 Save，然后 `EnqueueWatchedForUser`（换 PAT 后把本地已看重新入队，不在 401 当时回填）
- `DELETE /api/me/bangumi`：清 token 与该用户 outbox
- `POST /api/me/bangumi/sync`：入站同步，阻塞本次 HTTP。未绑 1001。Web/App 此接口单独超时 **120s**，不得走默认 10s

**EnsureCollection**：先 GET 收藏。已收藏（200）= 成功，不 POST，**不改用户现有收藏 type**。404 才 POST `{"type":3}`。禁止把「已看过」改回「在看」。

**映射**：`local.ep_number == int(ep)`；`ep==0` 时退 `int(sort)`。对不上 = 成功跳过并 `DeleteBangumiOutbox`，**禁止留行让 Drain 空转**。

**Drain**（出站，看完后台推，不阻塞 `ReportProgress`）：映射不到或 PATCH 成功都删该行。Drain 路径**任一 401**（`/v0/me`、收藏 GET/POST、episodes GET、PATCH）一律 `DeleteBangumiToken` + `DeleteBangumiOutboxByUser`，停止该用户后续请求。换 PAT 成功后再 `EnqueueWatchedForUser` 回填。串行间隔至少 350ms（仅 Drain）。

**章节分页**：按上游 limit 上限分页，禁止假定一页拉完。本篇章节 `GET /v0/episodes` 现网 limit **200**；收藏章节 `GET /v0/users/-/collections/{id}/episodes` 现网 limit **1000**。`offset += 本页条数`，直到本页 < limit。

**入站 429**：库大时可能撞 429。已拍板用 120s 硬等、**不改成作业**。429 记日志，**跳过该番**继续下一部，不把整次 sync 打成 9999。入站只把 Bangumi `type==2` 标看过；不把未看覆盖本地已看。入站 `position=0` 不覆盖本地正数。无 `bangumi_id` 不同步。

## 四、前端

### 4.1 路由与守卫（router/index.ts）

路由（懒加载）：`/setup`、`/login`、`/`（home）、`/animes`、`/animes/new`、`/animes/:id`、`/animes/:id/watch/:epId`、`/admin/users`，通配符重定向 home。`HomeView` 仍最近入库，不接 `GET /progress/continue`。`AnimeAddView` 仍手填路径，不接 `GET /library/dirs`。管理员详情页提供重绑；配错番在 Web 改。

`createAppRouter(history, setupStatusLoader)` 工厂便于测试注入 `createMemoryHistory()` 和可控 status；生产默认导出仍用 `createWebHistory()` + 真实 `getSetupStatus`。

守卫顺序：
1. 调 `/setup/status` 检测 configured（失败按"已初始化"处理）
2. 未初始化->强制 `/setup`；已初始化访问 `/setup`->跳 `/login`
3. `authStore.initialize()` 恢复会话（带并发去重）
4. 已登录访问 `/login`->跳安全 redirect（限站内，防开放重定向）
5. `requiresAuth` 且未认证：若 `token && !initialized` **不**跳登录（会话恢复中/网络失败保留 token）；否则跳登录页。`isAuthenticated` 仍是 `token && user`，不要改成只看 token。`requiresAdmin && !isAdmin` 可回 home。

测试基线：`router/index.test.ts`、`stores/auth.test.ts`、`stores/theme.test.ts`（Vitest + jsdom + `@vue/test-utils`）。生产 `vue-tsc -b` 继续排除测试文件；`tsconfig.test.json` 单独对测试和测试环境做类型检查。`npm run test:run` 固定先执行 `test:typecheck`，再运行 Vitest，测试类型错误会直接使命令失败。

### 4.2 Stores

- **auth**：token/user/initialized；`isAuthenticated`/`isAdmin`；`initialize/login/logout/setSession`。token 存 `localStorage('fan_web_token')`，code2001/401 自动清 token 跳登录。
- **app**：仅 `siteName`。
- **theme**：`ui`（modern/cinema/glass/apple）+ `accentColor` + `UI_ACCENT`；`setUi` 持久化 `localStorage('fan_web_ui')` 并写 `html[data-ui]`。

### 4.3 四套 UI 及其布局组件

| UI 风格 | 布局组件 | 特征 |
|---|---|---|
| modern（现代·默认） | `layouts/Analytics.vue` | 顶部 sticky navbar，主色绿 |
| cinema（影院深色） | `layouts/CinemaLayout.vue` | 左侧 232px 侧栏 + 戏剧红 + Cinzel 衬线标题 |
| glass（玻璃拟态） | `layouts/GlassLayout.vue` | 顶部悬浮毛玻璃 dock + 大圆角 |
| apple（苹果浅色） | `layouts/FluentLayout.vue` | 顶部磨砂导航 + 白色大圆角卡片 |

切换机制三层：
1. `stores/theme.ts` 的 `applyUiStyle` 设置 `<html data-ui="...">`
2. `themes.css` 对 `html[data-ui='cinema'|'glass'|'apple']` 覆盖设计令牌 + 组件形状差异（`:root` 即 modern 基线，在 `style.css`）
3. `index.html` 内联脚本在 `<head>` 同步读 `localStorage.fan_web_ui` 并设 `data-ui`，实现首屏前应用避免闪烁

导航栏 `ThemeSwitcher.vue` 切换；`App.vue` 依 `themeStore.ui` 动态渲染对应布局组件。

### 4.4 播放器与字幕（WatchView.vue）

- 基于 ArtPlayer。进入播放页时先用 Axios Bearer 请求 `POST /api/episodes/:id/media-token`，随后视频流 URL 使用当前集的短期 `media_token`（支持 HTTP Range），不把长期登录 JWT 放进 URL。票据在过期前 5 分钟预刷新；`switchQuality` 重载并保留进度。`video:error` 在 `mediaTokenRefreshInFlight` 或 `pendingResumeAfterReload>=0` 时忽略。续期成功（含 early return 同票）清空 `playerError`；`switchQuality` 失败时重置 pendingResume。
- **字幕**：字幕轨道列表使用 Axios Bearer 请求；指定轨道的 VTT URL 复用当前集的 `media_token`。`track.label` 只在赋给 `html` 时转义（先 `&`）。
- **切集并发保护**：每次加载递增序号；切集后迟到的旧媒体票据或其他异步响应会被忽略，不得创建旧集播放器。
- **进度上报**：每 10 秒节流上报 + 暂停/退出/播放完成时上报。`destroyPlayer` 在 `currentTime<1` 时不上报。90% 以上标记 watched，使用串行 Future 链（`reportChain`）避免并发覆盖。
- **断点续播**：进入播放页先查进度，position > 0 则在 `loadedmetadata` 后 seek。
- **系统更新页**：`stale_old` 时隐藏/禁用「立即更新」，`handleUpdate` 直接返回。

## 六、关键注意点（踩坑记录）

1. **`backend/web/dist/index.html` 占位文件被构建覆盖**：`.gitignore` 忽略 `backend/web/dist/`，但占位 `index.html` 此前被强制 commit。`build.sh` 会 `rm -rf` 后 copy 新产物 -> 该 tracked 文件显示 modified/deleted **属正常**，勿回滚，勿提交。

3. **Cinema 布局切换菜单定位**：Cinema 把 `ThemeSwitcher` 放左下角，默认菜单向下/向右展开会溢出屏幕。`themes.css` 已加 `html[data-ui='cinema'] .theme-menu { top:auto; bottom:calc(100%+8px); right:auto; left:0 }`（向上、向左展开），并在 `@media(max-width:860px)`（Cinema 变顶部横条）恢复向下靠右。
4. **管理员改密不生效**：见 §3.6，`InitAdmin` 只在无管理员时创建，改 config 不更新已有账号。
