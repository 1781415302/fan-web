# 阶段五交接文档：自动入库与 UI 优化

## 1. 阶段目标

实现视频目录与番剧库的双向自动同步，并整体美化前端界面。

**本阶段完成后系统状态**：
- 在 `video.root_path` 下新建一个含视频文件的子目录，Watcher 自动解析目录名、搜索 Bangumi：
  - 标题精确匹配 → 自动创建番剧并扫描集数入库
  - 无法精确匹配 → 进入「待入库」队列，由管理员在 `/library` 页面人工选择 Bangumi 条目确认入库
- 番剧关联的目录被删除 → Watcher 自动删除该番剧记录（episodes、watch_progress 由外键级联清理）
- 已入库番剧目录中新增/删除/重命名单集视频文件 → 自动增删/更新对应集数记录
- 前端新增「库同步」页面（管理员），并全站 UI 优化（骨架屏、进度条、集数网格、公共样式抽取等）

**本阶段不包含**：Nginx 配置、HTTPS、部署（阶段六）；封面图本地缓存下载；基于 fsnotify 的文件系统事件监听（明确不用，见注意事项）。

### 3.6 WatcherService 设计（services/watcher.go）

结构体：

```
type WatcherStatus struct {
    LastRunAt      time.Time `json:"last_run_at"`
    Running        bool      `json:"running"`
    AddedAnimes    int       `json:"added_animes"`
    RemovedAnimes  int       `json:"removed_animes"`
    NewPending     int       `json:"new_pending"`
    SyncedEpisodes int       `json:"synced_episodes"`
    Message        string    `json:"message"` // 最近一次运行的文字总结，出错时写错误原因
}

type WatcherService struct {
    scanner  *ScannerService
    bangumi  *BangumiService
    interval time.Duration
    trigger  chan struct{} // 容量 1，手动触发信号
    mu       sync.Mutex    // 保护 lastStatus
    lastStatus WatcherStatus
}
```

构造函数 `NewWatcherService(scanner, bangumi, cfg config.WatcherConfig)`，interval 取 `cfg.IntervalSeconds * time.Second`。

公开方法：
- `func (w *WatcherService) Start()` — 阻塞循环，由 main.go 以 goroutine 启动：先立即执行一次 `runOnce`，然后 `time.NewTicker(interval)`，每次 tick 或收到 trigger 信号时执行 `runOnce`。单 goroutine 顺序执行，天然无重入。
- `func (w *WatcherService) TriggerNow()` — 非阻塞写 trigger（`select + default` 丢弃已有信号）。
- `func (w *WatcherService) Status() WatcherStatus` — 加锁拷贝返回。

#### 3.6.1 runOnce 执行步骤（核心逻辑，必须按此顺序）

常量：`maxSearchesPerRun = 5`（单轮最多 5 次 Bangumi 搜索），每次搜索调用之间 `time.Sleep(500 * time.Millisecond)`。

1. `dirs, err := scanner.ListSubDirs()`
   - **失败（根目录不存在/不可读）：记录错误到 status.Message，直接结束本轮，不做任何删除动作**（安全规则：根目录异常时绝不能删库，可能是挂载盘没挂上）
2. 加载 `animes` 全量路径：`database.ListAllAnimePaths()`（见 3.7），构建 `map[string]int64`（file_path → anime_id）
3. 加载 `pending_animes` 全量（含 ignored），构建 `map[string]*models.PendingAnime`（dir_name → 记录）
4. **删除检测**：遍历步骤 2 的 map，`file_path == ""` 的跳过；`file_path` 不在 dirs 中的 → `database.DeleteAnime(id)`，`RemovedAnimes++`，`log.Printf("[Watcher] 目录消失，删除番剧 %q (id=%d)", ...)`
5. **清理失效待入库记录**：遍历步骤 3 的 map，dir_name 不在 dirs 中的 → `database.DeletePendingAnime(id)`
6. **逐目录处理**（遍历 dirs，排序后的顺序）：
   - **情况 A：`pathMap[dir]` 存在** → `syncEpisodes(animeID, dir)`（见 3.6.2），变更数累加到 `SyncedEpisodes`
   - **情况 B：`pendingMap[dir]` 存在**（无论 pending 还是 ignored）→ 跳过
   - **情况 C：新目录** → `handleNewDir(dir)`（见 3.6.3）；若本轮搜索次数已达 `maxSearchesPerRun`，剩余新目录留到下一轮（不建 pending 记录）
7. 更新 lastStatus（加锁）：LastRunAt=now，Running=false，各计数，Message 写形如 `本轮：新增 1，删除 0，待入库 2，同步集数 3` 的总结

全程任何单条记录处理出错（某目录扫描失败、某次入库失败）只记日志并继续处理其余目录，**不中断本轮**。

#### 3.6.2 syncEpisodes(animeID, dir)

1. `scanned := scanner.Scan(dir)`；出错则跳过该番剧（记日志）
2. `dbEps := database.ListEpisodesByAnimeID(animeID)`
3. 以 `ep_number` 为键比对：
   - 扫描结果有、DB 没有 → 收集为新集数，`database.AddEpisodes(animeID, newEps)`
   - DB 有、扫描结果没有 → 收集 ID，`database.DeleteEpisodesByIDs(ids)`（文件被删，级联删该集进度）
   - 两边都有但 `file_path` 不同（文件被重命名/替换）→ `database.UpdateEpisodeFilePath(episodeID, newFileName)`
4. 有任一变更时记一条 `[Watcher]` 日志

#### 3.6.3 handleNewDir(dir)

1. `has, err := scanner.HasVideoFiles(dir)`；err 或 `!has` → 直接返回（空目录/下载中目录不处理，避免 qBittorrent 建空目录产生 pending 垃圾）
2. `title := parseTitleFromDirName(dir)`
3. 若本轮搜索配额已用完 → 返回（下轮再处理）
4. `items, err := bangumi.Search(title)`，搜索配额 +1：
   - `errors.Is(err, ErrBangumiNotFound)`（无结果）→ 建 pending 记录（parsed_title = title），`NewPending++`，返回
   - 其他 error（网络故障等）→ **不建 pending**，记日志，下轮自动重试，返回
5. **精确匹配规则**：遍历 items，若 `normalizeTitle(item.Name) == normalizeTitle(title)` 或（`item.NameCn` 非空且 `normalizeTitle(item.NameCn) == normalizeTitle(title)`）→ 取第一个命中的条目自动入库；**不做模糊/包含匹配**（避免把第一季错配成第二季）
6. 命中 → `importAnime(dir, matchedID)`；未命中 → 建 pending 记录，`NewPending++`

#### 3.6.4 importAnime(dir, bangumiID)（自动入库与手动确认共用）

放在 WatcherService 上作为公开方法 `func (w *WatcherService) ImportAnime(dirName string, bangumiID int) (*models.Anime, error)`，handler 的确认接口直接调它：

1. `subject := bangumi.GetSubject(bangumiID)`
2. `database.CreateAnime(&models.Anime{Title: subject.Name, TitleCn: subject.NameCn, BangumiID: subject.ID, Cover: subject.Cover, Summary: subject.Summary, EpCount: subject.TotalEpisodes, FilePath: dirName})`
3. `episodes := scanner.Scan(dirName)`（出错不阻断，番剧已建成，用户可手动重扫）
4. `episodes` 非空时 `database.ReplaceEpisodes(anime.ID, episodes)`
5. 返回创建的 anime

#### 3.6.5 两个纯函数（同文件内）

- `parseTitleFromDirName(name string) string`：
  1. 反复剥离**开头**的 `[...]` 整体（字幕组标签），正则 `^\s*\[[^\]]*\]\s*`，循环直到不再匹配
  2. 反复剥离**结尾**的 `[...]` 整体（分辨率/格式标签）
  3. 下划线 `_` 替换为空格，`strings.TrimSpace`
  4. 结果为空则返回原始目录名
- `normalizeTitle(s string) string`：
  - `strings.ToLower` 后删除所有空白与标点：空格、`-_!?:;'".,&~`、半角与全角括号、方括号（用一个字符类正则替换为空串）

### 3.8 WatcherHandler 与路由（handlers/watcher.go）

```
type WatcherHandler struct {
    watcher *services.WatcherService
}
```

接口全部要求登录 + 管理员，路由注册在 `main.go`（与现有 admin 组并列，独立一个组）：

```
watcherGroup := protected.Group("/watcher")
watcherGroup.Use(middleware.RequireAdmin)
```

| 方法 | 路径 | handler | 行为 |
|------|------|---------|------|
| GET | `/api/watcher/pending` | `Pending` | query `include_ignored=1` 时含 ignored；返回 `{ items: [...] }` |
| POST | `/api/watcher/pending/:id/confirm` | `Confirm` | body `{ bangumi_id: number }`；流程见下 |
| POST | `/api/watcher/pending/:id/ignore` | `Ignore` | `SetPendingStatus(id, "ignored")` |
| DELETE | `/api/watcher/pending/:id` | `Remove` | `DeletePendingAnime(id)`（目录还在的话下轮会重新识别） |
| POST | `/api/watcher/scan` | `TriggerScan` | `watcher.TriggerNow()`，立即返回 `{ triggered: true }`，不等结果 |
| GET | `/api/watcher/status` | `Status` | 返回 `watcher.Status()` |

**Confirm 流程**（严格按序）：
1. 解析路径参数 id，`GetPendingAnimeByID`；不存在 → 404 语义的错误码（用 `utils.CodeNotFound`）
2. status 必须为 `pending`，否则 `utils.CodeInvalidParams`「该记录已被忽略，请先移除后重新扫描」
3. `scanner.DirectoryExists(record.DirName)` 为 false → `utils.CodeInvalidParams`「目录已不存在」
4. `anime, err := watcher.ImportAnime(record.DirName, bangumiID)`；失败按 `utils.CodeInternal` 返回并附 err 信息
5. `DeletePendingAnime(record.ID)`
6. `utils.Success(c, anime)`（前端拿 anime.id 跳详情页）

参数绑定、错误处理风格对齐 `handlers/anime.go`（`ShouldBindJSON`、bangumi_id 必须 > 0）。

### 4.3 库同步页（views/LibrarySyncView.vue）

页面结构自上而下：

1. **页头**：eyebrow「库管理」+ h1「库同步」+ 描述文案「自动监视视频目录，新番剧自动匹配入库，目录删除自动清理。」+ 右侧「立即扫描」按钮
2. **状态条**：一行小字展示 `WatcherStatus`：`最近扫描：{last_run_at 格式化}` + `{message}`；`last_run_at` 为零值时显示「尚未扫描」。「立即扫描」点击后：调 `triggerScan` → 轮询 `getWatcherStatus`（每 2 秒一次，最多 15 次，直到 `running == false` 且 `last_run_at` 晚于点击时刻）→ 刷新待入库列表
3. **显示开关**：checkbox「显示已忽略条目」（默认关），切换时重新 `listPending`
4. **待入库列表**：每个 `PendingAnime` 渲染一张卡片（`.pending-card`），内容：
   - 顶部：目录名（等宽字体，如 `font-family: monospace`）+ 解析出的候选标题「识别为：{parsed_title}」+ 状态徽标（ignored 时显示灰色「已忽略」）
   - 搜索区：一个输入框（初始值 = parsed_title）+ 「重新搜索」按钮；卡片挂载时自动以 parsed_title 调一次 `searchBangumi`（复用现有 `api/bangumi.ts`）
   - 结果列表：样式直接参照 `AnimeAddView.vue` 的 `.search-item`（封面缩略图 + 名称 + 集数 + 两行简介截断），点击选中高亮
   - 操作按钮行（选中结果后「确认入库」才可点）：
     - 「确认入库」primary → `confirmPending(id, selected.id)` → 成功后 `router.replace({ name: 'anime-detail', params: { id: anime.id } })`（与 AnimeAddView 一致）
     - 「忽略」secondary（status=pending 时显示）→ `ignorePending` 后刷新列表
     - 「移除」danger ghost → `window.confirm` 确认后 `removePending`，提示「移除后若目录仍存在，下次扫描会重新识别」

## 7. 注意事项

1. **不要用 fsnotify**：轮询方案足够（2-5 人规模、分钟级延迟可接受），避免新增依赖和 WSL/网络文件系统上的事件丢失问题。这是明确的架构决策，不要改。
2. **删除安全是最高优先级**：只有「根目录可读、子目录确实不在列表里」才删番剧。根目录本身异常时跳过一切删除。宁可漏删，不可误删。
3. **精确匹配策略是刻意的**：模糊匹配极易把多季番剧错配（如「进击的巨人」配到最终季）。宁可进 pending 人工确认，不做猜测。不要自行放宽匹配规则。
4. **Bangumi 限流**：Bangumi 对高频请求会封 IP。单轮最多 5 次搜索 + 每次间隔 500ms 是硬约束。`GetSubject` 在 confirm 流程中由用户操作触发，无需额外限速。
5. **并发安全**：SQLite 已 `SetMaxOpenConns(1)` + WAL，Watcher goroutine 与 HTTP handler 并发读写是安全的。Watcher 不持有任何跨轮的内存状态（目录清单每轮重新读库读盘），因此 confirm 接口与轮询并发时最坏只是一次重复搜索，无数据竞争。
6. **`file_path` 为空的番剧**（关联根目录本身）永远不参与删除检测和剧集增量同步，这是既有手动添加流程允许的形态，保持兼容。
7. **pending 的 dir_name 复用问题**：用户删掉 pending 记录后目录还在 → 下轮重建 pending，这是预期行为，不是 bug；彻底屏蔽请用「忽略」。
8. **前端轮询扫描状态**时务必在组件卸载时清掉定时器（对齐 AnimeListView 中 `onBeforeUnmount` 清 timer 的写法）。
9. **日志规范**：Watcher 所有日志带 `[Watcher]` 前缀，方便排查；不要在轮询里对「无变化」打日志（每轮无变化时保持静默）。
10. **运行环境提示**（本机开发）：go 位于 `/home/bishe/go/bin/go`（GOROOT 与 GOPATH 同目录，警告可忽略），node 可用 `/home/bishe/.qoder-server/bin/4ee322f78fe8606b0bcb6dd6991c61463b3112de/node`；项目根目录 `dev.sh backend|frontend` 可一键启动。
